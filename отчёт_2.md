# ДЗ2. Передача обращения человеку

Реализовал `needs_human`, `Draft`, сборку `Ticket`, промпт с собственными примерами и обработку пачки. Модель извлекает признаки, решение о человеке принимает код. Возврат передаётся человеку строго при сумме больше 5 000 рублей, повторное списание - больше 15 000; остальные условия проверяются по признакам регламента.

В `Draft` сохранены проверки цитаты и всех номеров платежей по исходному тексту. Ошибочный JSON исправляется через стандартный цикл проверки (до 3 попыток). Ошибка одного обращения не прерывает пачку, порядок ответов сохраняется.

## Замеры

Модель `deepseek-flash`, замеры 04-05.10.2026, температура 0, `max_tokens=600`, до 4 обращений параллельно с общим ограничением 10 запросов в минуту. Локальный кэш ответов отключён; кэш провайдера учитывается в расходе. Настраивал решение только на `dev`; `test` запущен один раз после фиксации решения.

## Какие правки помогли

- Разделил покупателя и продавца, уточнил новый возврат и исключения для спора через банк, статуса возврата и перевода СБП. Добавил два собственных контрастных примера к двум исходным; в итоговом промпте 4 примера, включая случаи с передачей человеку и без неё.
- Уточнил спорные границы категорий: комиссии, поддерживаемые карты и повторные технические запросы.
- Во второй итерации уточнил назначение SMS-кода, непоступившую оплату и отличие вопроса о возможном списании от подтверждённого списания. Полный отказ создания платежей через API явно отнёс к срочности 5.
- Отделил неясную жалобу на текущий сбой от общего справочного вопроса по срочности.

Обращений с расхождениями стало 0 вместо 8 из 60. Категория: 95.00% → 100.00%. Нужен ли человек: 95.00% → 100.00%. Срочность до балла: 96.67% → 100.00%. Схему прошли 60/60 до и 60/60 после правок.

Правки проверены вместе, поэтому отдельный вклад каждого примера не измерен. Рост качества сопоставляю с исправлением конкретных строк таблицы; случайный разброс модели полностью не исключён.
